# Project audit and provisional GW4 plan

Audit date: 2026-09-06 UTC (September 5 in Edmonton).

## Findings and changes

1. **Live optimization excessively rewards avoiding popular players.** The
   objective subtracts `rho * EO * xPts` from starters and captains. At the old
   live default `rho=1`, EO of 100% removes the entire forecast reward; EO above
   100% makes it negative. This is a preference for differential exposure,
   not an expected-points or expected-rank improvement. The live default is now
   zero, with `--rho` exposed for deliberate experiments. Historical backtest
   defaults are unchanged. Solver metadata records rho, alpha and beta.
2. **Historical clubs could override current clubs.** Live recommendations now
   use the latest bootstrap club and price across the future horizon, including
   owned players absent from predictions. A summer or deadline-day transfer
   must count against the new club's three-player limit. Historical rows remain
   untouched.
3. **Calculated selling prices rounded odd profits in the wrong direction.**
   A player bought at 70 and now worth 73 must sell for 71, not 72 (tenths).
   Corrected the optional projection path and cost-basis fallback. Snapshot
   selling values still take precedence when the predictor is disabled.
4. **Live cache misses performed unnecessary historical evaluation.** Removed
   the historical fold rebuild before predict-only: it cannot generate future
   fixtures, and trains the model stack before training it again for live use.
   Existing historical caches remain usable. No measured runtime speedup or
   prediction accuracy improvement is claimed.

## Remaining performance priorities

- Persist fitted models with fingerprints of training data, feature code and
  configuration. Predict-only still retrains on every invocation. Prediction
  caches currently key only on season/train seasons and can survive code changes.
- Add deadline-time, per-fixture feed freshness/coverage to recommendation output;
  distinguish bookmaker-backed forecasts from defaults before trusting a horizon.
- Fix historical ownership point-in-time leakage before using rho sweeps as
  evidence: season scoping prevents cross-season mixing but latest snapshots
  within a season still reveal later ownership. Historical position and cheapest
  candidate queries also use current information and need season/PIT review.
- Validate early-season minutes, forward goal calibration and DefCon against
  finalized per-player outcomes. GW4 immediately loses the GW1–3 prior while
  having only two completed matchweeks of features at this audit.
- Do not normalize summed anytime-scorer probabilities directly to total goals:
  probabilities count distinct scorers, not goals. Any experimental normalization
  should operate on implied goal intensities, account for incomplete player
  coverage and be assessed in shadow mode.
- CI skips database-dependent leakage/constraint tests when PostgreSQL is absent.
  Add a disposable migrated PostgreSQL service to exercise those checks in CI.
